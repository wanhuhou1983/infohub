# ADR-002: 图片存储——本地缓存 + 腾讯云 COS 双写

- **状态**: Accepted
- **日期**: 2026-04-29

## 背景

InfoHub 采集公众号、RSS、B站等文章时，需要处理文章中的嵌入图片。图片存储方案经历了三次架构迭代：

| 阶段 | 提交 | 方案 | 核心问题 |
|------|------|------|---------|
| v1 | `40ee992` | EasyImages 外部图床 | 外部服务不稳定，依赖第三方可用性 |
| v2 | `18a557f` | 图床 + 本地存储混合 | 同上，复杂度增加 |
| v3 | `587f045` | 纯本地存储 (`data/images/` + `/api/images/` 路由) | **OB 阅读视图无法渲染相对路径** |
| v4 | `a9eb590` | 本地 + 腾讯云 COS 双写（当前） | — |

v3 的核心问题：Markdown 中使用 `/api/images/{source}/{hash}.{ext}` 相对路径，**在后端 Web 页面中工作正常**（因为浏览器请求发向后端），但在 **Obsidian 阅读视图**中无法渲染（OB 将相对路径解析为本地文件系统路径，而非 `http://localhost:3001/...`）。

## 决策选项

### 方案 A：纯本地存储 + 保持相对路径（v3）

- 图片存 `data/images/`，Markdown 用 `/api/images/` 相对路径
- 优点：零外部依赖、无需云费用
- 缺点：OB 阅读视图图片断裂；仅后端 Web 页面可正常显示

### 方案 B：纯 COS（无本地回退）

- 图片仅上传 COS，Markdown 用 COS 绝对 URL
- 优点：OB 可渲染
- 缺点：COS 不可用时图片全部断裂，无缓存；需要公网访问才能下载

### 方案 C：本地优先 + COS 增强（双写，最多一次失败回退）

- 图片**同时**保存本地 + 上传 COS
- OB Markdown 优先使用 COS 绝对 URL
- COS 上传失败时自动回退到 `/api/images/` 本地相对路径
- 优点：**三级降级**（COS → 本地 /api/images/ → 隐藏），任一环节失效不阻断采集
- 缺点：存储空间翻倍、COS 费用

### 方案 D：本地 + 静态文件服务器

- 图片存本地，通过 Nginx/Caddy 静态托管
- 优点：无需云服务
- 缺点：需要额外部署静态文件服务器；不满足"单机可运行"的架构原则

## 决策

**选择了方案 C：本地缓存 + COS 双写（最多一次失败回退）**。

技术细节详见 [`docs/image-storage-plan.md`](../image-storage-plan.md)。

## 理由

1. **OB 阅读视图不可妥协**：InfoHub 的核心输出之一是 Obsidian 知识库，图片可见性是基本要求。只有绝对 URL 才能在 OB 阅读视图中渲染。

2. **本地回退保证健壮性**：采集流水线不能因为图床不可用而阻塞。COS 上传失败时自动降级使用 `/api/images/` 本地路径，采集任务继续执行。

3. **COS 作为唯一外部依赖是可控的**：相比 EasyImages（第三方图床，可能有服务中断/策略变更），腾讯云 COS 是标准对象存储，配置稳定，费用极低（图片访问量不大）。

4. **MD5 去重**：基于内容 MD5 去重，同一 URL 的相同图片不重复上传。

5. **本地始终是完备备份**：回滚到纯本地模式只需清除 COS 配置，无需迁移数据。

## 后果

### 正面

- OB 阅读视图图片正常渲染
- 采集流程对 COS 不可用有弹性（自动降级）
- COS 绝对象 URL 可在其他场景复用（分享、嵌入等）
- 历史遗留图片可通过迁移脚本补传（参见 `cos-image-migration` skill）

### 负面

- 存储空间翻倍（本地一份 + COS 一份），但图片体积较小，可接受
- 采集时增加了一次 COS 上传操作（异步、不影响主流程）
- 需要维护 COS 凭据（`~/.cos/cos.conf` 或 `.env.json`）
- OB 依赖外部网络才能渲染图片（离线时看不到图）

### 配置

COS 凭据配置源优先级：`.env.json` → `~/.cos/cos.conf`。两者都不可用时跳过 COS 上传，纯本地运行。
